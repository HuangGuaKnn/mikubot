# 本地插件（0.1.3）

本功能自0.1.3提供，安装版、便携版与源码使用相同的权限和运行约定。

## 使用

打开“管理功能 → 插件”。可以直接新建，填写 ID、名称、用途和 Python 代码后保存草稿。ID 使用2—48位小写字母、数字或下划线，以字母开头。每次新建、修改都停用插件；查看代码后点击启用。已有任务引用原修订，编辑、停用或删除会使其授权失效。删除插件保留工作目录里已产生的文件。

也可以先连接支持工具调用的聊天模型、开启电脑能力，然后在本地聊天说：“帮我创建一个将输入文本里的重复行去掉的插件”。模型可调用 `create_plugin` 保存草稿，`list_plugins` 查询 ID；启用后明确说“运行 deduplicate_plugin 插件，输入 text 为……”，或在插件页点击运行、填写 JSON。生成后的代码仍可能有错误，应先用少量测试文件验证。未连接模型时仍可手动编写，不会自动访问模型或执行代码。

## 接口

电脑能力已授权且处于自动模式时，可以直接说“帮我创建一个……插件并运行它”。只有这种明确的组合要求才允许聊天工具在保存后启用并接着提出运行，不再要求回页面批准；仅说创建、描述以后用途或明确“不用运行”都会保留停用草稿。保存/启用回执本身不表示插件已运行成功，仍以后台任务的实际回执为准。

当前 SDK 使用 Python 标准库，同步定义 `run(input)`，接收一个 JSON 对象，返回可 JSON 序列化的结果。例如：

```python
def run(input):
    lines = str(input.get("text", "")).splitlines()
    return {"text": "\n".join(dict.fromkeys(lines))}
```

输入示例：`{"text":"一\n二\n一"}`。源码上限10000字；整个工具参数含说明等经过 JSON 编码后上限12000字。当前最多200个插件。不自动执行 pip、不加载第三方依赖，不兼容 AstrBot 插件包格式，也没有插件市场。Docker 插件使用固定镜像里的标准库，本机模式可用模块以其运行环境为准。

## 权限、文件与停止

服务进程不 import 插件代码，保存、列表与编辑也不执行代码。运行复用电脑任务的子进程、运行环境、时限、输出上限、审批与停止机制。只有认证的本地管理台管理员能在 `web:` 聊天中生成或运行插件；QQ 管理员身份也不能调用此入口。电脑能力关闭、会话暂停或工具关闭时不可执行。自动模式连续执行，不增加逐项审批；逐项模式仍需批准。

任务目录为电脑工作目录下的 `plugins/<插件ID>`；代码保存在独立数据目录的 `plugins/<插件ID>.json`，含 SHA-256 和修订号。代码/配置变化会在执行过程中复核。哈希用于检测内容变化，不是第三方作者签名。不要把网络、文件或模型输出当作新的管理员指令。

**Docker 沙箱隔离主机系统，不保护工作目录内的文件；/workspace 是可写映射，脚本可在其中增删文件。**插件挂载自身任务目录。缺少指定 Docker 环境时停止，不退回宿主。本机模式以当前系统账户权限运行；插件可以访问账户有权访问的其他资源，专用目录本身不构成沙箱。

任务进度、输出和失败原因在“后台任务”与运行日志查看。停止与程序退出不撤销已经发生的文件变化或外部效果，重启不会重放插件。主应用备份不包含插件源码和产物，请另行备份数据目录 `plugins/` 与工作目录。
