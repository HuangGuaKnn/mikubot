# mikubot 0.5

Windows 本地运行的 QQ 群友与助手，兼顾自然聊天、记忆、群黑话与办事。默认预置人格只有 **初音未来**。本版整合名称与触发配置、无 wait 的 Planner、显式共享记忆、人格兴趣探索及自然长度分段，修复整合前审查确认的七项问题。

## 解压使用

1. 解压 `mikubot-0.5.0-Windows-x64.zip`，保留整个 `mikubot` 文件夹。
2. 双击 `mikubot.exe`，管理台会在浏览器打开。普通用户无需安装 Python、Node 或数据库。
3. 填写兼容 Chat Completions 的模型地址、模型名称与密钥，测试后保存。
4. 先在本地试玩，再选择 NapCat、SnowLuma 或 QQ 官方机器人，填写允许列表。

聊天与规划质量取决于你配置的模型。程序不内置收费模型、免费额度或演示 AI 回复。未配置模型时，显式记忆、群词典、待办、明确提醒、计算和词法检索仍可用。开启 Planner 会增加模型请求，可指定独立模型。

## 名称、Planner 与群聊

“设置与连接”可设置机器人称呼与别名；产品名称仍为 mikubot。响应 @、回复机器人、提及名称分别有开关。“群与会话”可继承或覆盖，展示实际生效值。名称触发支持“初音未来，记住：……”等明确命令，原始消息保持完整。

Planner 判断消息在对谁说、是否值得回应、准备说什么、需要哪些资料；Replyer 组织最终文字。计划只有 **reply / skip**，没有 wait、等待后重判或概率抽签。开启后，@ 和叫名也会结合语境判断；引用、转述或询问他人可以不回复。主动参与考虑已有答案、话题结束、参与价值与人格兴趣，并受活跃度、安静时段、冷却和预算限制。

指定私聊可开启“每条必回复”；关闭 Planner 时按已启用信号与会话策略直接回应，不增加 Planner 调用。必回复仍遵守总暂停、允许列表与预算。无模型时只对直接触发使用标明的本地规则，不能模拟语义判断。

连续短消息合并是独立设置，默认合并延时 0，最多合并同一成员 8 条／3 张图。停止消息或同一成员的新请求会打断旧回复及未开始的工具；已发送消息与已执行操作保留实际状态。

## 记忆与可控共享

自动整理先产生候选，确认后使用；支持来源、版本、人物画像、事实冲突、纠错与遗忘。中文词法检索可直接使用；Embedding 默认关闭，需兼容 `/embeddings` 的独立模型，费用计入预算。

默认会话隔离。需要共享时，让相关会话加入相同“共享记忆空间”，再对具体记忆勾选“允许共享”。只共享已确认、群可见且明确允许的长期记忆；私有记忆、原始聊天、会话摘要、黑话、表达、任务和回执仍按会话保存。共享资料保留原会话与原用户身份，不按昵称合并人物。

退出空间、撤销共享、停用源会话、QQ 撤权、纠错或删除会使相关检索和派生上下文失效。每次模型外发前及各段发送前复检来源。删除无法撤回此前已经发给模型或已经送达的内容；原始聊天及历史备份可另行管理。

文件导入支持 TXT、MD、CSV、JSON、PDF、DOCX，单文件最多 8MB／30 万字。PDF 需文字层，最多 300 页，无扫描 OCR。长文件按片段召回；向量冷启动每次最多新增 12 个预选片段，可能遗漏缺乏词法线索的内容。

## 人格兴趣与网络知识

“人格工坊”可编辑兴趣，初音未来默认关注音乐与动画。“人格知识”与聊天记忆分开，展示公开来源、采集日期、有效期及“原文摘录／模型整理”标记。

定期探索默认关闭，需全局与单人格两个开关同时开启。默认每 24 小时、每天最多 6 次搜索、每次最多读 4 个网页、有效期 90 天，均可调整。按 UTC+8 持久记录预算，失败搜索也计次，重启不补跑积压任务。手动探索绕过定期开关，仍遵守暂停与次数上限。

探索只发送人格兴趣与公开网页，不读取其他聊天私事，不自动推送群聊。相同人格与来源去重更新；删除保留来源阻止自动重新学习；到期条目不用于回答。知识删除／更新时，依赖的旧回复、摘要、Planner 参考及工具请求重新检查。

入库前先检查标题与正文的主题相关性，过滤无关页面及低质量账号凭据列表；这仍是可解释的启发式检查，不能证明资料真实。搜索使用 Bing HTML 渠道，遇验证、限流、网络失败或页面变化会如实报告。资料可能不准确或过时，来源便于核对；模型不可用时仅保存明确标注的原文摘录。暂未提供完整的多来源事实核验与矛盾裁决。

## 自然输出与群语言

回复可以是几个字、一句或多句，不要求固定句数。QQ 长回复按目标长度与自然停顿分段，默认目标 160 字符、软上限 320、间隔 600ms、最多 8 段。链接、代码和组合字符保持完整；超过段数上限时合并余文，不截掉内容，因此末段或完整代码块可超过软上限。

各段关联同一逻辑回复，记录实际平台 ID 与送达状态；任一已发送段都能被识别为回复链。同一群分段组不交错。中途撤权、删源、新请求或送达未知会停止余下段，不自动重发整组。

黑话学习、理解、主动使用分别控制。自动发现需真实多人用例，候选必须审核；多义词按话题与例句检索。表达习惯独立管理，不当作事实或指令，不模仿群成员身份。网络热梗进入人格公开知识，不自动变成本群黑话。

## 记事、工具与回执

```text
初音未来，记住：我喜欢合作游戏
我的记忆
更正记忆：记忆ID → 新内容
删除记忆：记忆ID
我们群里“开饭”指一起打游戏
解释黑话：开饭
添加待办：检查资料
5分钟后提醒我喝水
每天晚上9点提醒我喝水
我的待办
取消任务：任务ID
计算：(12+8)*3
总结最近聊天
```

提醒按 UTC+8，支持一次性、每日、每周。电脑和 mikubot 运行、通道在线时才可送达；睡眠和关机期间不能准点发送。未知结果须核对后手动处理。

模型可调用有界的记忆、任务、计算和公开检索工具，执行入口校验明确请求与权限。同一请求多个不同待办可独立保存，同一操作重放仍去重。回执包含输入输出来源与版本，删除的资料不会通过旧回执追问重入上下文。缺少完整来源的旧回执可在管理页查看，但不作为模型资料。

可选 MCP 需发现目录、允许列表、会话权限，并对每次调用在本地逐次批准；结果未知不自动重试。支持 Streamable HTTP 有界 JSON／SSE，不支持 stdio、旧独立 SSE、OAuth、采样或异步 tasks。公网远端要求 HTTPS，本机可 HTTP，不连接局域网或云元数据地址。

工具记录最近最多 200 条，位于 `data/tool_runs.json`。损坏时保留原件、暂停 MCP、显示恢复入口，不阻止管理台启动；恢复不重放操作。配置损坏同样保留原件并暂停启动。协议细节见 [0.4 说明](docs/README-v0.4.md)。

## QQ 接入

NapCat／SnowLuma 需另行安装、登录，使用 OneBot v11 Universal WebSocket。正向填写 `ws://127.0.0.1:协议端口/...`；反向填写管理台显示的 `/onebot/v11/ws` 地址。两端连接密钥相同（至少 12 位），分别配置主人 QQ 号与群允许列表。

QQ 官方机器人填写 AppID／AppSecret 与群／用户 OpenID 允许列表。OpenID 不等于 QQ 号码；接收事件、群消息范围与主动发送权限由腾讯决定，不能保证全群旁听与协议端相同。

[NapCat](https://napneko.github.io/) · [SnowLuma](https://snowluma.github.io/) · [腾讯 SDK](https://github.com/tencent-connect/botpy)

## 数据、备份与升级

数据位于 EXE 同级 `data`。Windows 密钥由当前账户 DPAPI 保护，换账户或机器需重填。管理台只绑定本机；不要分享 `admin.token` 或带令牌链接。关闭浏览器不退出服务，可从托盘或管理台退出。开机启动默认关闭。

备份包含数据库、脱敏设置、人格知识及探索预算，不含模型／QQ／MCP 密钥、管理凭据、向量缓存及独立工具记录。恢复前校验并建立安全副本，恢复后暂停且连接关闭。兼容 schema 1 的 0.1—0.4 备份；旧备份没有人格知识时恢复为空库。

升级：先备份并退出旧版，新版解压到新文件夹；可在同一 Windows 账户复制完整旧 `data` 到新版 EXE 旁，或恢复备份。仅完全未修改的旧预置人格会被替换／移除，自建及改写人格保留。旧会话保存的覆盖设置也保留，可在会话页改为继承。内部 Python 包与数据库名继续为 `qunyu`，兼容旧数据，无需手动改库。保留旧目录便于回退，不要只复制 EXE。

## 开发与验收

源码需要 Python 3.12，普通用户只需便携包：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m qunyu
.\.venv\Scripts\python.exe -m pytest -q
powershell -ExecutionPolicy Bypass -File scripts/build.ps1
```

预算按本地估算或服务返回用量，工具 Schema 与参数计入估算。模型配置各自排队，不同配置可并行，全局原子预留输入／输出预算；未知消费保留估算，真实账单以服务商为准。后台与聊天共用配置时仍顺序排队，没有严格的后台抢占调度。

参见 [整合前审查](docs/REVIEW-2026-10-16.md)、[整合验收](docs/INTEGRATION-v0.5.md)、[测试报告](TEST_REPORT.md)。机制独立实现，不宣称覆盖 AstrBot／MaiBot 全部功能或在真实模型上超过它们。
