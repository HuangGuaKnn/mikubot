# 生成时决定消息边界（0.1.3）

默认 `output.mode: model`。自然对话生成前，提示词要求模型自行决定独立消息的边界，用一个空行分隔；单换行属于同一条内的排版。可以只有几个字、一条一句，也可以一条包含多句，不规定必须发几条。不另发一次模型请求重新分段，不按标点或目标字数猜边界。

例如模型直接生成：

```text
嗯，今天还不错。

刚刚听完一首喜欢的歌。感觉心情也轻松了一点。
这一行仍属于同一条消息。

你呢？
```

发送为三条；中间这一条含两句话与一个单换行，保持完整。模型没有空行时整条发送，程序不会补切。只有空白的段不会发送。代码围栏内部的空行、完整JSON对象/数组不会被当作独立消息分隔。

新回复在原聊天正文之外保存 `metadata.reply_parts`，API同时返回 `reply_parts`。本地聊天使用这些已保存的边界显示消息；旧记录保持原样，不按新规则重切。UI只显示与原正文一致的段落，用户消息不使用此元数据。

## 设置

“机器人配置 → 回复与记忆 → 自然消息分段”默认选择“模型自然分段”。已有设置没有 `mode` 时也使用新默认。会话可以单独覆盖：

```json
{"output":{"enabled":true,"mode":"model","interval_ms":600,"max_parts":8,"platform_max_chars":1800}}
```

`max_parts` 是防刷屏上限，不强制分满；模型超出时只合并尾部，不丢正文。关闭分段后保持一条，仍受平台发送上限保护。`target_chars`、`max_chars` 仅在主动选择兼容模式 `mode: length` 时生效，正常模式完全不使用这两个旧参数。界面将旧参数折叠展示。

## 发送边界

消息超过通道长度保护上限时，仍必须进行传输切分；完整链接、代码或字符不能完整容纳时停止发送，原文留在本地。这是异常长度保护，不承担日常聊天分段。每条仍检查权限、来源和请求是否有效；未知或失败回执停止后续条，不盲目重发。官方QQ的被动回复序号按实际发送条数连续编号，后续表情包也继续使用实际序号。

模型是否遵守排版规则取决于模型能力；不遵守时优先保留完整回复，不额外付费重写。测试使用模型与QQ协议替身，不代表真实QQ风控、付费模型分段风格已验收。参考项目的公开生成/后处理扩展机制可见[MaiBot Hook文档](https://docs.mai-mai.org/plugin/hooks)；本实现直接要求首轮生成确定边界。
