# 0.1.5 开发与服务器验证记录

本记录覆盖 0.1.5 的功能实现与预发布验证。服务器实测阶段使用了 0.1.4 开发构建；正式交付以 0.1.5 发行资产及其校验文件为准。

## 修复范围

- 自动更新：直接替换程序、独立助手、配置与数据备份、固定端口重启、失败回退，远程更新由宿主授权。
- 人格蒸馏：区分网络断流与正常结束但思考耗尽输出额度，结算已知用量；在任务配额内重试、扩大输出额度或采用已配置备用模型，不执行残缺工具调用。
- 长期记忆：累计消息与空闲整理、持久整理游标、每日上限、明确可靠且无冲突的事实/偏好/事件自动确认，低置信度和冲突继续待审。昨天/昨晚等时间查询按配置时区补查原始消息。
- 可视化：记忆与黑话的状态统计、七日新增图、全部/当前会话、分页、来源、审核与修改，整理失败可见。
- 黑话：默认群间共享确认后的词义，独立于记忆隔离；私聊和原始群聊例句不外传。新聊天默认学习，保留明确关闭的会话配置；有明确释义及高置信度才自动确认。
- 人设资料：住址/活动地点、职业/身份、年龄、生日、作息、背景、关系称呼，均可留空且随人格统一使用。
- QQ 图片：服务器先下载并验证图片内容，再发送内联图片给视觉模型；连接器只有文件标识时尝试 get_image，失败明确提示，不用文字假装识图。
- QQ 分段：延长回执等待，持久记录已确认/未知/未发送状态，提供仅补发从未尝试发送的后续段落。未知段落不会自动重复发送。

## 服务器实测

已在服务器隔离目录使用现有配置的 Gemini 备用模型，完成和泉纱雾的完整 7 次蒸馏分析，返回人格草稿，实际总用量 25,851 tokens，未自动应用人格。另核对 3 张已有 QQ 图片，服务器均成功下载并验证格式。生产数据已做独立备份。

推理模型的短额度请求实测正常返回 finish_reason=length 和 [DONE]，但全部完成 token 用于思考，无正文；这不属于网络断流。没有移除真正的流完整性检查。

## 尚需用户真实场景观察

QQ 风控与对方客户端最终展示不能仅凭 OneBot 成功回执保证；程序保留每段回执与不确定状态。Windows 冻结 EXE 的独立助手验收结果见本次发行的测试报告。

参考能力来自 [LivingMemory](https://github.com/lxfight-s-Astrbot-Plugins/astrbot_plugin_livingmemory) 与 [Self Learning](https://github.com/NickCharlie/astrbot_plugin_self_learning)，实现独立编写，没有复制其 AGPL 源码进入 MIT 主项目。


## 本地回归结果

完整后端回归 1,531 项通过，3 项跳过；18 个前端交互检查全部通过。真实源码程序测试完成同端口替换、重启及记忆保留；文件替换中途故障和健康检查失败的数据恢复用例通过。浏览器验收已检查记忆图表、黑话页面与学习设置保存。


## 部署后检查

服务器服务已恢复，固定端口 8765，SnowLuma 已连接。已为已登录管理员启用远程版本切换权限；权限由宿主配置保存，远程页面不能自行开启。程序与数据的完整备份保留在服务器私有目录。

后台自动整理已实际新增 3 条有效记忆，进度可跨重启保存；约 1.4 万条记忆的概览接口单次约 139 毫秒。该耗时仅指统计概览，不是全部召回请求的性能承诺。现有待审内容没有被批量自动确认。


## 0.1.5 Windows 成品验收

完整源码回归 1531 项通过、3 项跳过，18 组前端检查通过。实际冻结程序完成直接更新成功和健康检查失败回退，均保持原端口、密码、记忆及未知个人文件；安装器覆盖保护与数据保留通过。正式源码、成品和校验信息以 0.1.5 发行附件为准。
