# GitHub 版本与更新

> 一键更新自0.1.3提供。0.1.1/0.1.2升级到0.1.3时仍使用原有安装窗口，升级后可使用一键更新。

自动更新沿用现有程序与数据目录，保留桌面、开始菜单的快捷方式，不重新创建或覆盖自定义入口；首次安装时仍可自行选择是否创建。

当前版本为0.1.3，提供安装版、便携版和源码包。更新源固定为公开仓库[iownmmiku/mikubot](https://github.com/iownmmiku/mikubot/releases)，不会读取你的模型密钥或要求GitHub Token。

## 在软件内操作

1. 打开右上角“版本与更新”，点击“检查 GitHub 版本”。打开入口只读取本地状态，不自动访问GitHub。
2. 默认只显示正式发行版；按需开启“显示测试版”，或翻页查找历史版本。
3. 选择版本、下载类型，查看发行说明后点击“下载所选版本”。下载目标按版本固定，不使用可能变化的latest下载链接。
4. 下载显示进度，可取消。文件大小与SHA-256均通过后，才提供“保存已校验文件”。校验值来自GitHub发行资产的digest，或同一发行版中绑定文件名的SHA-256清单。缺校验信息时请去发行页面人工核对。

检查有60秒缓存。GitHub网络不可用、限流、文件被替换、下载中断、校验失败或空间不足会明确停止；不会修改正在运行的程序，不会自动重试安装。下载暂存在实际数据目录的`updates`中，与程序文件分离。已完成的下载可重启后继续取用，安装前会再次检查文件；未完成的下载需重新开始，不支持HTTP断点续传。

## Windows安装版

### 一键更新（0.1.3起）

在本机右上角“版本与更新”检查并选好版本，点击“一键更新到 v…”。确认后由后台完成下载、大小和SHA-256校验；校验通过后再次检查是否还有后台任务或模型请求。没有活动任务才暂停新的写入与模型请求、退出程序，再由独立Windows助手静默运行安装器。安装器等待原进程退出、使用分阶段替换，助手随后以原 `--data-dir` 重新打开软件。

下载阶段可以取消；交接安装后不再取消。文件损坏、活动任务、环境不支持或校验失败不进入安装。安装失败后会尝试打开原目录内的软件；旧进程或安装器仍未退出时，不强杀、不重复启动。结果在数据目录的 `updates/install-result.json`，详细安装输出在 `updates/install.log`，下次打开更新页可看到结果。程序成功安装但未能重新打开时，可用原快捷方式启动。

此实现针对Windows x64安装版。源码、便携、Linux/Docker保持下面的手动更新，避免覆盖源码改动。完整应用备份不包含所有密钥和外部文件，更新前建议保存独立数据目录的完整副本。已有安装器提供写入失败恢复；本功能不包含升级后启动健康检查失败时的数据库与程序自动回退。

### 保留安装窗口

运行于Windows x64、且程序目录具有有效安装记录时，已校验的安装包会提供“退出并启动安装”。该入口只允许在运行mikubot的电脑上操作；远程WebUI可以查版本和下载，不能启动安装。后台任务仍在运行时会要求先完成或停止任务。

确认后，下载的安装器等待当前进程完整退出，再显示原有安装窗口；不会强制结束进程。安装器使用分阶段写入和失败恢复流程，保留独立的数据目录，并在更新后启动、桌面快捷方式和停止入口中继续携带原有`--data-dir`。当前数据与程序目录相互包含时，自动安装会停止，需先将数据移到独立目录。

自动衔接要求目标版本至少为0.1.1，并且不低于当前版本。相同版本可重新安装；历史版本仅下载，不直接覆盖降级。升级前建议完全退出后保存完整数据目录副本；旧程序未必能读取新版数据，升级不等于提供数据库降级迁移。

## 便携版、源码和服务器

- **便携版**：下载对应ZIP，完整退出软件后解压到新目录，再启动；继续使用原有数据目录。
- **源码部署**：下载源码ZIP到新目录，按[源码部署指南](SOURCE_DEPLOY.md)准备依赖并启动，使用同一个数据目录；不会自动执行git pull、切换分支或覆盖未提交改动。
- **Linux、Docker及其他环境**：下载源码并按原部署流程更换代码或构建镜像。此入口不直接重建容器。

0.1.0安装包没有此功能，请手动安装0.1.3；0.1.1/0.1.2可通过软件内的更新入口选择0.1.3，并完成原有安装窗口。GitHub列表只显示实际已发布的版本。

## 更新来源与边界

只接收固定仓库的已发布Release和约定文件名，草稿与无效版本号不列出。下载全程使用HTTPS，重定向仅允许GitHub及指定发行文件CDN；不提供任意URL或第三方镜像执行入口。SHA-256验证文件与发行信息一致，不是独立代码签名，也不能防止仓库发布账号本身被攻破。

接口依据：[GitHub Releases API](https://docs.github.com/en/rest/releases/releases)、[发行文件API](https://docs.github.com/en/rest/releases/assets)。
